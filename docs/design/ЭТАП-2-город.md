## Как работаем (цикл одного аспекта)

**Каждый аспект — работа в НОВОМ чате** (постоянное правило заказчика,
2026-10-21: реализация каждого следующего аспекта/этапа начинается
в новом чате; этот чат закрывается после приёмки).

Заказчик начинает новый чат одной строкой (шаблоны — в AGENTS.md,
раздел «Как заказчику начать новый чат»):
`git pull, работаем по ЭТАП-2, аспект N «Название»` — агент сам читает
AGENTS.md → PLAN.md → этот файл → дизайн-док аспекта.

1. Берём **ОДИН** аспект из списка ниже, по порядку.
2. Агент задаёт уточняющие вопросы по аспекту → заказчик отвечает.
3. Решения фиксируются в дизайн-доке модуля (разделы 3 и 6), агент
   показывает план работ.
4. Реализация: баланс → `data/*.json`, логика → `*_sim.gd`, показ →
   `*_view.gd`/`*_hud.gd`, строки → `loc/ru.json`; тесты `test.bat` ×3
   и живой прогон `city.tscn` (процедура — в `AGENTS.md`).
5. Заказчик играет. **Аспект принят, только когда принимается без правок.**
   Только тогда переходим к следующему.

## Правки v1.20.0–v1.20.1 — жизнь деревни (2026-10-22, ЖДУТ ПРИЁМКИ)

Второй чат правок по замечаниям заказчика. Ключевые системы (детали —
CHANGELOG_E2.md, правила — [01-город.md](01-город.md)):

- **Зоны**: только Поле и Пастбище (слои, жилая зона и кварталы вырезаны;
  поле ставится сразу с репой, культуру меняют кликом по грядке).
- **Жители-кружки**: цвет = основная специальность; эффективность
  по цветам (своя ×1.0 / доп. ×0.7 с размыванием −0.08 за цвет /
  чужая ×0.35 / голем ×0.75; `city.json → work_colors`).
- **Жильё**: один дом — один человек; пара с детьми — один дом,
  освободившийся дом возвращается деревне.
- **Главная площадь 2×2** у спавна: место сбора и планёрки, костёр;
  строить нельзя в радиусе 3 клеток; переносится игроком.
- **Голем-староста** («Белый властелин»): белый кружок, не житель
  (не ест, не болеет, не стареет, не женится), последний резерв
  жизненно важных мест; гибнет — у площади пробуждается новый.
- **Утренняя планёрка**: распределение по приоритетам (профильные цвета →
  жизненно важные → остаток) с контролем дефицитов и причин конфликтов;
  план в `day_plans`, летописи и `user://city_debug.log`.
- **Тултип кружка** (имя/путь/мысли) и **анти-застревание** жителей
  (ежедневный сторож).
- **v1.20.1**: видимый рост поля (дни вместо секунд, процедурные растения
  со свечением спелых); вечерний снос продукции работником на склад/центр;
  саженцы (33% с дерева, 1-2) и автопосадка у лесопилки лесорубом
  (добыча растёт, гнев леса тоже); липкие цели жителей.

### Устав голема-старосты (вставка заказчика; реализована в morning_plan)

> Ты — Белый голем-староста деревни. На утреннем тике после загрузки
> сохранения ты размещаешь требуемые здания, собираешь жителей на
> планёрку и распределяешь их по приоритетам: сначала жители с актуальным
> цветом — на профильные производства; при конкуренции выбирается
> наиболее компетентный; затем жители без нужного цвета — на жизненно
> важные объекты: еду, ресурсы и строительство; остаток — на вторичные
> задачи, резерв или работу через дополнительные цвета с пониженной
> эффективностью. Староста белый и не подчиняется цветовым бонусам
> жителей. Возвращай ежедневный план структурированно, отмечай
> использование дополнительных цветов со штрафом, незакрытые критически
> важные объекты и причины выбора при конфликтах.

В коде устав реализован детерминированно (без внешнего ИИ):
`city_sim.gd → morning_plan()`, шаги 1–4 и формат плана — там же.

## Решения, уже зафиксированные (не переспрашивать)

- Здание при повышении уровня города достраивается: докидываются ресурсы,
  обновляется до нового размера — если вокруг есть место.
- Предел населения на релиз — **150**; свыше (без союзного города) —
  эмиграция самых неумелых к фракциям/в бандиты.
- Дом = 2 взрослых + дети, пока не выросли.
- Схематичный режим — временная мера до появления спрайтов.
- Ремонт — 40% стоимости в ресурсах; перенос зданий — бесплатно.
- Размер поля = сколько способен обработать фермер; мастерство растёт,
  при нужде фермером может стать другой житель.
